## 심각도순 문제
### 1. P1 — 작은 글씨와 큰 컨테이너의 불균형
화면에서 보조 글씨가 지나치게 작고, 소스에 8–10px 크기가 반복된다. 큰 카드와 패딩은 확보했지만 실제 내용을 읽기 어렵다. 본문 14–16px, 메타정보 12–13px, 모바일 입력 16px를 출발점으로 정하고 제목/본문/보조정보 3단계를 일관되게 적용한다. 카드 안쪽 여백은 16/24px, 섹션 간격은 24/32px 체계로 정리한다. 대비는 실제 렌더링에서 측정한다.

### 2. P1 — 연구의 핵심보다 운영 정보와 카드 구조가 먼저 보임
연구 화면에서 할 일·운영 섹션이 연구 질문보다 먼저 나오고, 결과 화면도 설정·편집 UI가 분석보다 앞선다. 인박스에는 항목이 없는 큰 카드가 반복된다. 홈은 오늘 실행할 작업, 연구는 질문·현재 판단·다음 행동, 결과는 대표 결과·해석·검증·출처를 먼저 보여준다. 비어 있는 인박스 구획은 하나의 상태 요약으로 합치고 비어 있지 않은 작업만 펼친다. 판단과 검증 상태는 실제 canonical 상태를 표시하며 UI에서 임의 추론하지 않는다.

### 3. P1 — 구현 오류가 사용자 화면의 중심을 차지함
AI 인박스에 Gmail OAuth 환경변수명이 포함된 오류가 그대로 표시된다. 연결 배지는 개별 기능의 가용성과 차이가 나고, 로컬은 P0 연결 실패로 로그인부터 막힌다. 로컬 장애를 운영본 전체 장애로 일반화할 수는 없다. 사용자 화면은 '메일 연결 설정이 필요합니다'와 '연결 설정 보기'를 제공하고, 변수명·작업기·재시도 횟수는 진단 영역으로 보낸다. 연결 안 됨/조회 실패/실제로 0건을 구분한다. 인증 보호는 유지한다.

## 모바일
하단 내비게이션, safe-area 대응, 단일 열 전환은 좋은 기반이다. 그러나 706px 관찰은 휴대전화 검증을 대체하지 못한다. 9px 내비게이션 라벨, 작은 보조 버튼, 가로 스크롤 칸반, 고정 추가 버튼과 상세 콘텐츠의 간섭을 360/390/430px에서 확인해야 한다. 모바일 연구는 기본 목록+상세 전환으로 설계하고 보드는 선택 기능으로 둔다. 추가 버튼은 입력 키보드·상세 패널이 열릴 때 충돌하지 않게 한다. 터치 영역은 44px 목표로 검증한다.

## AI가 만든 듯한 패턴
문제는 AI 사용 여부가 아니라 제품과 무관하게 반복되는 구성이다. 동일한 둥근 카드, 빈 상태 카드, 작은 대문자 보조 라벨, 배지와 연결 상태의 상시 노출이 연구 내용보다 앞선다. 반복 카드를 목록·구분선·문서 구조로 바꾸고 연구 질문·출처·검증 상태가 시각적 특징이 되게 한다.

## 사용자 관점
- 처음 쓰는 사람: 아이콘 메뉴와 Vault/P0 용어로 첫 행동을 판단하기 어렵다.
- 숙련 연구자: 연구 질문·결과를 찾기 전에 운영 UI를 통과하고, URL로 맥락을 다시 열기 어렵다.
- 저시력·키보드 사용자: 작은 보조 텍스트, dialog 의미·포커스 처리의 불일치가 부담이다. 완전한 키보드/스크린리더 통과는 확인하지 않았다.
정서 흐름은 차분한 첫인상에서 다수의 연결 상태와 오류를 만나 불확실해지는 방향이다. 저장/승인 완료는 결과와 다음 행동을 확인해주는 마무리가 필요하다.

## 전체 리빌딩 계획
1. 제품·화면 명세: 12개 화면의 목적/첫 정보/주요 행동/데이터 출처/오류 상태를 정리하고 PRODUCT.md·DESIGN.md 초안을 만든다. 기존 데이터와 권한 의미를 유지한다.
2. 공통 뼈대: 팔레트·타입·간격·상태 토큰, 실제 접히는 메뉴, URL 기반 이동, 공통 폼·dialog·오류 패턴을 정한다.
3. 핵심 흐름: 홈 → 연구 → 결과 → 자료를 먼저 다시 구성한다. 대표 프로젝트 하나로 정보 위계와 긴 제목·빈 데이터·검증 실패를 확인한다.
4. 수집과 정리: 인박스·메일·학교 공지·캘린더를 연결하고 승인/실패/재시도/완료를 통일한다. 설정·바로가기·레거시 진입도 정리한다.
5. 모바일·접근성: 360/390/430/768/1440px, 200% 확대, 키보드, 입력 키보드, 긴 한국어·일본어 제목, 네트워크 실패를 검증한다.
6. 전환: 핵심 흐름의 동등성이 확인된 화면부터 교체하고 중복 테마·사용하지 않는 스타일을 정리한다. 기능 추가는 별도 범위로 둔다.
완료 기준: 첫 화면에서 다음 행동 식별, 결과에서 출처·검증 접근, 새로고침/뒤로가기 맥락 유지, 모바일 내용/버튼 가림 없음, 연결 실패와 0건의 명확한 구별.
