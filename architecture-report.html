Core shape. The app has two main runtime paths: browser → Next.js → repository/providers, and browser → loopback Bridge → machine-local state. Microsoft Graph is a browser-side provider call inside the first picture’s integration boundary; it does not pass through Next.js.

One workspace,
two execution planes.

03 / DATA JOURNEYS

Three paths through the system.

The shared browser shell reaches different owners depending on the capability. Each path has its own transport and state boundary.

01 / Research files

Repository reads and edits

App Router handlers call domain loaders and VaultRepository. The repository selects GitHub or a configured local checkout. Text writes carry the current GitHub SHA so stale edits can be rejected.

Workspace→Next API→Vault adapter→GitHub / disk
02 / Results bundle

Workbook to dashboard

The Python exporter reads source workbooks and emits three dashboard JSON documents. The Results endpoint loads the bundle and checks its schema and passing validation status before the panel uses it.

XLSX→Exporter→3 JSON docs→Results API
03 / Local work

Browser to loopback

Mail, planner, inbox, and portal actions call 127.0.0.1 directly. The Bridge validates origin and token, dispatches jobs, and persists machine-local state without a Vercel hop.

Panel→Loopback API→Jobs→JSON / SQLite

Results scope. The dashboard’s validation document reports exporter-only checks. The UI consumes generated analysis; it does not recalculate the thesis workbook methodology at request time.

04 / RUNTIME & TRUST

State follows the owner.

The hosted runtime and the local Bridge do not share one transaction or one store. A browser action can coordinate them, but each side commits through its own boundary.

07 / ARCHITECTURE READOUT

What the topology makes clear.

These are properties visible in the current source, rather than deployment guarantees.

01

The browser is the integration seam.

It is the only shared surface between hosted routes, direct Microsoft Graph requests, and machine-local Bridge operations.

02

Repository mode is an adapter choice.

GitHub and local filesystem reads share the Vault-facing interface; writes use path checks and source-specific conflict behavior.

03

Results are published artifacts.

The exporter owns workbook-to-JSON transformation. The UI reads the generated bundle and enforces its document contract.

04

Local domains have separate storage.

Inbox and Planner use Vault JSON paths; Mail and Portal maintain distinct SQLite databases and job state.

05

Cross-runtime actions can partially complete.

Hosted routes and the user’s Bridge have no distributed transaction. Features that touch both sides need explicit retry or recovery behavior.

06

Companions are at different maturity levels.

The Windows wallpaper host shares Bridge startup; the Android and Windows widget projects remain proof-of-concept surfaces.
